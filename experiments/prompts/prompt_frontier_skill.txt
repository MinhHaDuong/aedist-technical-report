You are an expert Claude Code developer. Write a complete, production-ready Claude Code custom slash command (skill) for energy data extraction from government PDFs.

## Skill specification

**Name**: `/extract-energy-table`

**Purpose**: Given a PDF document URL or local path, extract structured energy data tables (power plant inventories, capacity statistics, generation data) into clean CSV format with source provenance.

**Usage examples**:
```
/extract-energy-table https://example.gov/pdp8-report.pdf
/extract-energy-table ./data/evn-annual-report-2023.pdf --format csv --lang vi
/extract-energy-table ./report.pdf --tables "capacity,generation" --output extracted/
```

## Required deliverables

### 1. Skill definition file
Write the complete skill YAML/markdown definition that Claude Code expects, including:
- Skill name, description, and trigger conditions
- Input parameters with types and defaults
- The full system prompt that instructs Claude on how to perform the extraction
- Any tool requirements (Bash, Read, Write, WebFetch)

### 2. Supporting Python script
Write a Python script (`extract_energy_table.py`) that the skill invokes, which:
- Accepts a PDF path or URL as input
- Uses an open-source PDF extraction backend (pymupdf4llm, marker, or pdfplumber)
- Extracts tables from the PDF, handling:
  - Multi-page tables that span page breaks
  - Vietnamese text with diacritics (UTF-8)
  - Merged cells and complex header structures
  - Units in headers (MW, GWh, %, tấn)
- Outputs clean CSV with:
  - Normalized column headers (English, snake_case)
  - Source provenance: filename, page numbers, extraction timestamp
  - Data types: numeric values cleaned of thousand-separators and unit suffixes
- Has `--format` flag supporting csv, json, markdown
- Has `--lang` flag for Vietnamese/English source documents
- Uses argparse with sensible defaults
- Includes logging, not print statements

### 3. Test file
Write `test_extract_energy_table.py` with:
- Unit tests for header normalization (Vietnamese → English mapping)
- Unit tests for numeric cleaning (e.g., "1.200 MW" → 1200.0)
- Unit tests for CSV output format validation
- A mock PDF test using a fixture (no real PDF needed for unit tests)

### 4. Integration instructions
Explain how to install the skill:
- Where to place the skill definition file
- Required Python dependencies (add to pyproject.toml)
- How to test the skill locally before committing
- Example CLAUDE.md entry to document the skill for team use

## Technical constraints
- Python 3.10+ (use modern type hints: `list[str]`, `X | None`)
- No `from typing import List, Dict, Optional`
- Dependencies must be installable via `uv add`
- The script must work standalone (`python extract_energy_table.py file.pdf`) and as a Claude Code skill
- Follow the existing project conventions: argparse for CLI, logging module, no hardcoded paths
- Tests use pytest, no subprocess calls in unit tests

## Quality bar
- The code should be production-ready, not a sketch
- Handle edge cases: empty tables, malformed PDFs, mixed-language content
- Error messages should be actionable ("No tables found on pages 1-5" not just "Error")
- The skill prompt should be detailed enough that Claude consistently produces correct extractions
